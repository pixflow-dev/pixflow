How it works

Four checks. One transaction. Zero guessing.

The router never decides what is real by itself — that is not computable on-chain. A keeper resolves off-chain from on-chain facts, the registry publishes the verdict, and the router enforces it.

1

Keeper resolves

An off-chain resolver watches Pons launches and resolves each symbol to its canonical token from on-chain facts only: earliest launch, progress dominance, socials match, graduation status.

What can go wrong: the resolver can be slow — a verdict that arrives after buyers already bought the clone protects no one. Speed is the product's hardest problem.

→
2

Registry publishes

The verdict goes on-chain in the Canonical Registry. Fail-open changes wait a 1-hour timelock, in full public view; defensive flags — contest, wash, dev-dump — take effect immediately.

What can go wrong: the registry is a trust point. A compromised keeper key can re-point a symbol after 1h. The timelock buys time to react; it is not a veto.

→
3

Router verifies

On every buy the router checks: the curve comes from the Pons factory registry (never from the caller), the token is the registered canonical for its own symbol, no flags are set, the curve is open, and the snipe-tax window has passed.

What can go wrong: nothing moves here — if any check fails, the transaction reverts with a specific reason (NotCanonical, TaxWindow, …) and no fee accrues.

→
4

Buy executes — or reverts

All checks pass: the buy executes on the curve in the same transaction. Tokens go straight to the buyer, unspent ETH is refunded in the same transaction, and the 0.3% fee accrues only on the executed buy.

What can go wrong: on a capped buy (you send more than the remaining allocation) the fee is still 0.3% of the full amount sent — even though the excess is refunded.

Honest caveats

What Pixflow does not do.

A verification router that hides its limits is just another clone. These are stated in the README, and they stay stated here.

The registry is a trust point

The keeper decides which token is canonical. A compromised keeper key can re-point a symbol at a clone — after a 1h timelock, in full public view, and any defensive flag raised in that hour cancels the proposal. Production ownership should be a multisig.

"Real" is not "good"

The router answers "is this the real DCTY?", not "is DCTY a good buy?". The canonical token can still dump after graduation — graduates do, routinely.

Capped buys still pay the full fee

If you send more ETH than the remaining sellable allocation, the router buys the whole allocation and refunds the rest in the same transaction — but the 0.3% fee is charged on the full amount you sent.

v1 limits

Native-ETH quotes only — no ERC-20-quoted curves (USDG, NVDA). minTokensOut is a strict quantity bound: the router fails closed where the curve would partially fill at the same price.
